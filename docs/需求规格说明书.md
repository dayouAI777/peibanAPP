7. 「设计点表情进去，用户发消息可以带表情，回复也可以带表情」
8. 「放开了开发」

## ① 项目概述

一款自用 AI 虚拟陪伴 App。用户自由描述想要的人，AI 解析成人设空间并查缺补漏，定稿后成为一个**不可更改**的固定角色；之后像发微信一样聊天，角色带表情、记得住长期的事、偶尔主动找你，并能从 Git 仓库在线升级。

解决的是：通用 AI 没性格、聊完就忘、人设可以随意改来改去导致「不像同一个人」。

## ③ 版本迭代规划

**V1.1（本版已实现）**
- 配置门禁：填 Key → 真测一次链接 → 才准入人设
- 人设唯一、定稿只读；12 维人设空间、AI 查缺补漏、7 项必填本地判定
- 记忆窗口 1000 句可调；旧对话按 50 条一批压成摘要，缓存复用
- 用户行为记录手册：AI 判断 + 9 条内置硬规则；可查看、逐条删、可关
- 双向表情：用户点选插入、AI 按规则自然使用；三档频率
- 在线升级：仓库 `version.json` → 版本比对 → 下载 APK → 系统安装
- SQLite v2 迁移（保留旧聊天，旧人设提示重建）

**V1.2【AI建议】**：长期记忆权重与衰减、手册条目编辑、表情包自定义、升级包签名校验。
**V2【AI建议】**：多角色、语音、角色分享、iOS 正式打包。

## ⑧ 技术选型方案

> 实测：Flutter 3.50.0 / Dart 3.14.0 · JDK 21 · Android SDK 36 · Gradle 9.5.0 · AGP 9.3.1 · 版本 1.1.0+2。

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Flutter | 一套代码跨端，聊天列表性能好 |
| 大模型 | DeepSeek `deepseek-chat` | 用户指定；OpenAI 兼容格式 |
| 人设解析 | `PersonaAnalyst` + `completeJson` | 让模型吐结构化 JSON；必填判定与兜底留在本地，不信任模型自报完成度 |
| 上下文 | `ContextBuilder` + `MemoryService` | 分层：system 放人设/手册/摘要，messages 放最近原文按字符预算裁剪；旧对话 50 条一批压摘要并缓存 |
| 行为手册 | `UserManualService` | AI 给候选（含 evidence 与 confidence），本地 9 条硬规则一票否决 |
| 表情 | `EmojiKit` + `EmojiPicker` | 同一套池子两边共用；用系统 emoji，零图片资源 |
| 在线升级 | `dio` + `package_info_plus` + `open_filex` | 版本清单双源（raw / GitHub contents 接口），版本号用 buildNumber 比大小 |
| 存储 | `sqflite` v2 + `shared_preferences` | 4 张表：companions / messages / user_notes / memory_chunks |
| 状态 | `provider` | V1 够用 |

**几个明确的取舍**
- 1000 句不是「每次把 1000 句原文全发过去」：那样会撞模型上下文上限且按输入计费极贵。做法是旧对话压成摘要永久带着、最近原文按预算直发，本地全量保留不丢。
- 行为手册宁缺毋滥：隐私、临时情绪、无依据猜测一律不入库；用户可在界面里逐条纠正。
- 人设定稿不可改是产品原则，不是技术限制：数据库层故意不提供 `updateCompanion`，只留 `deleteEverything` 重建。
- 升级不做签名校验、不做强制升级——自用 / 小范围分享版，不做过量工程。
